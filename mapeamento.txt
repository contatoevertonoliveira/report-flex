**Autenticação e acesso**

- **LoginPage**
  - Arquivo: [LoginPage.tsx](file:///c:/Users/EvertonOliveira/Documents/Systems/Csharp/report-flex/ReportFlex.WebApp/src/pages/LoginPage.tsx)
  - Chama:
    - `api.signin(usuario, senha)` → `POST /api/login/signin`
      - Backend:
        - ASP.NET Core Minimal API.
        - Gera JWT com `Microsoft.AspNetCore.Authentication.JwtBearer` + `System.IdentityModel.Tokens.Jwt`.
      - Uso:
        - Recebe token, salva em `localStorage` via `setToken`, e grava também `rf_level` (nível do usuário).
    - (Opcional) `api.signinToken(token)` → `GET /api/login/signin-token?token=...`
      - Backend:
        - Valida um token de cliente e emite JWT de acesso.
  - Proteção de rotas:
    - [RequireAuth.tsx](file:///c:/Users/EvertonOliveira/Documents/Systems/Csharp/report-flex/ReportFlex.WebApp/src/components/RequireAuth.tsx) usa o JWT do `localStorage`:
      - Decodifica o payload (`decodeJwtPayloadSegment`) para checar expiração.
      - Redireciona para `/login` se token inválido.
    - Depende do middleware JWT do backend (biblioteca JwtBearer).

- **RequireNotClient / RequireSuperAdmin**
  - Também em [RequireAuth.tsx](file:///c:/Users/EvertonOliveira/Documents/Systems/Csharp/report-flex/ReportFlex.WebApp/src/components/RequireAuth.tsx)
  - Funcionamento:
    - Lê `rf_level` do `localStorage`.
    - Se nível = `Cliente`, bloqueia acesso a rotas de administração (ex.: Configurações, Clientes, etc.).
  - Backend:
    - Política `NotCliente` em [Program.cs](file:///c:/Users/EvertonOliveira/Documents/Systems/Csharp/report-flex/ReportFlex.WebApi/Program.cs#L20-L27) aplicada em rotas como `/api/admin/*`.

**Configurações de Banco (tudo que mexe em .env)**

- **SettingsPage (Configurações)**
  - Arquivo: [SettingsPage.tsx](file:///c:/Users/EvertonOliveira/Documents/Systems/Csharp/report-flex/ReportFlex.WebApp/src/pages/SettingsPage.tsx)
  - Chama:
    - `api.getDbMode()` → `GET /api/admin/db-mode`
      - Backend:
        - Lê `DB_MODE` da memória (carregado de `.env`).
    - `api.setDbMode('Real' | 'Demo')` → `POST /api/admin/db-mode`
      - Backend:
        - Atualiza `dbMode`.
        - Grava `DB_MODE` no `.env` via `SaveEnv` em [Program.cs](file:///c:/Users/EvertonOliveira/Documents/Systems/Csharp/report-flex/ReportFlex.WebApi/Program.cs#L74-L92).
    - `api.getConnections()` → `GET /api/admin/connections`
      - Backend:
        - Junta:
          - Override em memória (`realOverrides["CMS"/"Logins"]`) se existir.
          - Ou connection strings padrão do `appsettings.json`.
        - Usa `Microsoft.Data.SqlClient` só para validar e uso indireto (construção de `GetConn`).
    - `api.setConnections({ CMS, Logins })` → `POST /api/admin/connections`
      - Backend:
        - Atualiza `realOverrides["CMS"]` e `realOverrides["Logins"]`.
        - Persiste `DB_CMS_CONN` e `DB_LOGINS_CONN` no `.env`.
        - Usa I/O de arquivos (`System.IO`) e `LoadEnv/SaveEnv`.
    - `api.getDbInfo()` → `GET /api/admin/db-info`
      - Backend:
        - Abre duas conexões SQL:
          - `SqlConnection(GetConn("CMS"))`
          - `SqlConnection(GetConn("Logins"))`
        - Lista tabelas com:
          ```sql
          SELECT TABLE_NAME
          FROM INFORMATION_SCHEMA.TABLES
          WHERE TABLE_TYPE='BASE TABLE'
          ORDER BY TABLE_NAME
          ```
        - Retorno: `{ mode, databases: { CMS: { connection, tables }, Logins: {...} } }`
      - Bibliotecas:
        - `Microsoft.Data.SqlClient` para conexão.
        - ASP.NET Core Minimal API para montar resposta.
  - Resultado:
    - Essa tela é o “painel central” de configuração e diagnóstico de banco, tudo em cima de `.env` + SQL.
